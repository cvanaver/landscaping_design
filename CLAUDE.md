# Landscape Render Project

Purpose: generate photoreal previews of a planned backyard fence-line garden by inpainting onto real yard photos.

## What's in this directory (/west_fence_landscaping)

- `hero.jpg` — the source yard photo (user provides)
- `mask.png` — white where the planting bed goes, black everywhere else (generated by `make_mask.py`)
- `render_landscape.py` — main script: calls fal.ai Flux Fill Pro on the masked region
- `make_mask.py` — interactive GUI for painting the mask
- `renders/` — output directory for generated images (created on first run)
- `landscape_design_plan.pdf` — the install spec the renders should match

## Project context

- **Bed location:** along a stepped wood privacy fence, ~46 ft total run, three sections (168" / 153" / 228")
- **Plants:** Karl Foerster feather reed grass (back row, 12 total) + Echinacea OR Rudbeckia 'Goldsturm' (front row, 36 total)
- **Middle section is special:** no grasses (tree clearance), only flowers, bed narrowed to 18"
- **Location:** Wilmette / Evanston IL, USDA Zone 5b–6a, part sun

## How the user runs this

```bash
python make_mask.py          # interactive mask painting → mask.png
python render_landscape.py   # uploads to fal.ai, downloads renders → renders/
```

## Required environment

- Python 3.10+
- Packages: `fal-client`, `pillow`, `requests`
- Env var: `FAL_KEY` (from https://fal.ai/dashboard/keys)

## Conventions for Claude Code

- **Don't run `render_landscape.py` automatically** — it costs real money (~$0.30/run). Always show the user the cost estimate from `check_setup()` and wait for confirmation.
- **Prompts live at the top of `render_landscape.py`** in the `PROMPTS` list. Edit there to tweak language, lighting, plant cultivars, or add/remove variations.
- **Mask quality matters more than prompt wording.** If a render is bad, the first hypothesis is mask, second is prompt. Suggest re-running `make_mask.py` before tweaking prompts.
- **Image dimensions:** hero.jpg and mask.png MUST be identical pixel dimensions. The script validates this.
- **Resolution sweet spot:** ~1500×1100 (1.7 MP). Higher = more cost, marginal quality gain. Suggest downsizing if the user has a phone photo > 4 MP.
- **Preserve clause is critical.** Every prompt should end with the `PRESERVE_CLAUSE` constant — without it, the AI will redraw the fence/tree/house.

## Common user requests and how to handle them

| Request | Action |
|---|---|
| "Try a different flower" | Edit `PROMPTS` list; replace flower description, keep the Karl Foerster + preserve clause |
| "Render only one variation" | Trim `PROMPTS` to a single entry, or set `NUM_IMAGES_PER_PROMPT = 1` |
| "AI keeps changing the fence" | Tell user to re-run `make_mask.py` with a tighter mask. Don't edit prompts first. |
| "Add a winter render" | Add new entry to `PROMPTS`: "Late December, bare flower stalks, wheat-tan grass plumes, light snow, golden hour, photorealistic" |
| "Show year 3 mature" | Add prompt entry with "dense mature established 3-year-old planting, full coverage, no visible mulch" |
| "Compare both flowers side by side" | Already in default PROMPTS — both Echinacea and Goldsturm are rendered |

## Don't do

- Don't suggest other rendering tools (D5, Enscape, Reimagine Home) — this project has settled on Flux Fill Pro
- Don't propose adding more dependencies (no torch, no diffusers, no comfyui) — the whole point is using the hosted API
- Don't modify the `check_setup()` cost confirmation flow — the user wants explicit cost approval before each batch
- Don't read or modify the user's actual API key. If `FAL_KEY` is missing, tell the user to export it; never ask them to paste it in chat

## When making changes

1. Read `render_landscape.py` first to understand current structure
2. Make minimal, targeted edits — don't refactor the script
3. After changes: run `python -m py_compile render_landscape.py` to syntax-check
4. Don't run the full script unless the user explicitly asks (it costs money)
